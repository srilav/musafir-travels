Before we go further with Vercel — I need to flag a real blocker I just realized: the ALB only serves plain HTTP (per backend-spec.md's "no ACM cert/custom domain yet" decision), but Vercel always serves the frontend over HTTPS. Modern browsers block "mixed content" — an HTTPS page cannot call an HTTP API via fetch/XHR. If we deploy to Vercel as-is, every API call (login, signup, everything) will be silently blocked by the browser.

To fix this without buying a domain, the cleanest option is adding a CloudFront distribution in front of the ALB — CloudFront's default *.cloudfront.net domain gets a valid AWS-managed HTTPS certificate automatically, no custom domain required. It's within AWS's free tier for personal-scale usage (10M requests/month free), takes ~15-20 min to provision/propagate, and origin traffic (CloudFront→ALB) stays HTTP internally, which is fine.
